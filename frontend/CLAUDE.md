# frontend

The Next.js 16 app. The repo-wide standards in the root `CLAUDE.md` apply here too — this file
only covers what is specific to this tier.

## Read the framework's own docs first

Next.js 16 differs from model training data, and the framework says so itself. `AGENTS.md` in
this directory is generated by `next dev` and committed on purpose; it points at the
documentation shipped inside the package:

```
node_modules/next/dist/docs/          index.md, then 01-app/
```

Read the relevant page before writing code that touches routing, caching, server components,
cookies or data fetching. This is not a formality: reading `cookies.md` is what produced the
proxy architecture below instead of a plausible-but-wrong direct call with CORS.

`AGENTS.md` is machine-managed — `next dev` rewrites its block when it detects an agent. This
file is not: the generator leaves `CLAUDE.md` alone while `AGENTS.md` holds the managed block.
Deleting `AGENTS.md` makes it scaffold both again, so leave it in place.

## Layout

```
app/
  page.tsx                  redirects by session state
  login/                    client component; register and sign in
  dashboard/                server component, redirects when there is no session
  api/[...path]/route.ts    proxies the browser's calls to the API
lib/
  api.ts                    API_URL, shared types
  session.ts                getCurrentUser(), forwards cookies server-side
  problem.ts                reads ProblemDetails bodies
  __tests__/                Vitest, over lib/ only
e2e/                        Playwright specs, against a stack that is already up
```

## Commands

```
npm run dev             dev server; needs the API and Postgres up
npm run typecheck       tsc --noEmit
npm test                Vitest over lib/
npm run test:e2e        Playwright; needs `npx playwright install chromium` once
npm run build           production build (output: standalone)
```

Vitest is scoped by `vitest.config.ts` so it does not collect the Playwright specs, whose
`*.spec.ts` names its default glob would otherwise match.

## Invariants

- **The browser only ever talks to this origin.** `app/api/[...path]/route.ts` proxies to the
  API and carries the auth cookie both ways. That keeps the Identity cookie first-party, takes
  CORS out of the browser's path, and survives a deployment that splits the two across domains.
  Do not call the API directly from a component.
- **Server-side code reaches the API through `API_URL`**, which is `http://api:8080` in
  compose. It is never exposed to the browser and must not become `NEXT_PUBLIC_`.
- **Reading a session is server-side.** `getCurrentUser()` forwards the request's cookies to
  `/auth/me` and returns null on 401, so a page can choose between rendering and redirecting.
  Cookies can only be *written* from a Route Handler or a Server Function.
- **Every user-visible string is translatable.** `en-US` is the default and `pt-BR` is
  supported; nothing user-facing is hardcoded in a component. The backend sends codes, so this
  tier owns all display text, including error messages.
- **Formatting is this tier's job.** Weights, distances, durations and dates arrive canonical
  (kilograms, metres, seconds, UTC) and are converted and formatted here, at the render edge,
  never upstream.
- **Elements before ARIA.** A button is a `<button>`, an input has a label, and the keyboard
  reaches everything. Retrofitting accessibility is far more expensive than writing it.
- **Tests reach for `data-testid`.** Playwright selects on it rather than on visible text,
  because visible text is translatable and would make the suite locale-dependent.

## Fonts and assets

`next/font/google` was removed from the layout deliberately: it needs network access at build
time, which makes the Docker build flaky for no gain here. The app uses a system font stack.
